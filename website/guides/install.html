01 / RECOMMENDED FOR EVERYONE

Install the signed release.

  1. Open GitHub Releases. Choose the newest CodeC IDE release with an app-v* tag—not a userland-* bootstrap release. The version documented here is app-v1.3.18.
  2. Download the universal APK from Assets. For this version, the filename is CodeC-IDE-1.3.18-universal.apk. Choose the APK, not GitHub’s source-code ZIP. There is one universal APK; no separate CPU download to pick.
  3. Open the downloaded APK. Android may ask you to allow Install unknown apps for the browser or file manager you used. Enable that permission only for the app opening this trusted download, return and tap Install. You can turn the permission off afterward.
  4. Open CodeC. Follow the introduction or skip its educational steps, then read and acknowledge the privacy note. Getting Started explains what opens next.

Replacing a debug build? Back up first.

Debug and release APKs use different signing keys. Android cannot update one over the other: switching can require uninstalling the old app, which removes its private data. Export your projects to a safe location before uninstalling.

03 / KEEP YOUR WORK

Update deliberately. Back up first.

In CodeC, open Settings → About → Check for updates. This is a check you start, not an automatic background check. It considers only app-v* releases, compares versions numerically and refuses older versions. It never installs a userland bootstrap as an app update.

The updater verifies the release’s SHA256 before installation. A missing checksum opens the Releases page instead of silently bypassing verification. Updates signed with the same key normally keep your projects; keeping a backup is still a good habit.

Your safe switch to a fresh install

  1. In the Projects hub, open the ⋮ menu → Export all projects.
  2. Save the backup ZIP outside CodeC’s private storage, somewhere you can find after uninstalling. Check that you have the saved file before removing the app.
  3. Install the release, then use Import projects backup from the Projects hub menu to restore it.

A project backup contains source projects—not the Linux environment, app settings or GitHub token. Reconfigure and reconnect those after a fresh install. A single project can also be exported as a ZIP.

For known upgrade and device caveats, see the beta testing guide on GitHub.

04 / THE HONEST COMPATIBILITY NOTES

One APK. Different capabilities.

The APK minimum is Android 7.0 (API 24). Android 7/8 install tiers were not device-tested in the current beta notes. CPU architecture and Android execution restrictions also affect compiler availability.

Compiler availability by CPU architecture
Device architectureWhat to expect
arm64-v8aBuilt-in offline TCC. The optional downloadable Clang module also targets arm64. Android restrictions may still require fallback.
x86_64Built-in offline TCC. The optional Clang module is arm64-only, not an x86_64 toolchain.
32-bit ARM / x86No bundled TCC for these ABIs, and the arm64 Clang module is not a fix. A compatible external toolchain such as Termux may help where supported. Beta notes flag 32-bit boot/toolchain gaps; do not assume feature parity or successful startup.

Compiler selection is automatic: built-in TCC first, optional Clang when available, then Termux when the toolchain is blocked. There is no engine picker to set up.

05 / ONLY IF YOU NEED IT

Termux is a fallback, not step one.

On a supported device, try CodeC’s built-in compiler first. If Android blocks a toolchain or an executable does not match the CPU, the Output Panel provides fallback guidance. The old Termux Settings card is gone; fallback still works automatically when configured.

Set up the optional Termux fallback
  1. Install Termux 0.109 or later from F-Droid or Termux’s GitHub releases, on a device it supports.
  2. Open Termux itself and run the following commands, one line at a time. These are not CodeC terminal commands.

Run inside Termux only

echo "allow-external-apps=true" >> ~/.termux/termux.properties
termux-reload-settings
pkg update && pkg install clang
  1. In Android, open Settings → Apps → CodeC IDE → Permissions → Additional permissions and allow Run commands in Termux environment. Android labels can vary.
  2. Return to CodeC and retry the build. No engine selection is required.

Keep Termux’s packages in Termux. Do not add official Termux package repositories to CodeC’s own package environment.

06 / SEPARATE FROM THE RELEASE CHANNEL

Looking for a branch build?

Developers can open GitHub Actions, choose a successful Build APK run and download its Artifacts. GitHub may require sign-in to download artifacts.

  • CodeC-IDE-debug — debug-key build, intended for development; it does not update over a differently signed release.
  • CodeC-IDE-release — upload-key-signed release build from that run, not necessarily a published app release.

For normal installation, use the signed APK attached to an app-v* release instead. Always export projects before changing signing channels.
