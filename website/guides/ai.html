Set up your own provider

  1. Use a disposable project with only your own non-sensitive code. Open the AI rail slot → AI home.
  2. Choose Google Gemini (default). Obtain your own key using the app’s Get a key link. NVIDIA Build is a separate, manual dev/test-only option.
  3. Read the selected provider’s data-use terms and the 18+/terms confirmation. Save the key in CodeC, never on this website or in source files. Your key pays the provider’s bill.
  4. Optionally tap Test connection: it sends a fixed one-word request, no code. It is still a network request.
  5. Open chat and read Before you ask; choose I understand — start when ready. This agreement is not an Android permission.

Gemini terms apply; the guide notes paid keys only in the EEA, Switzerland and UK. NVIDIA’s trial terms are separate. There is no CodeC server, shared key or proxy. The app links to the provider’s key page; do not send secrets to a chat or paste your key into this website.

Check before sending

  1. Open a harmless project. Ask a short question, or choose Explain selection, Explain last error, Ask about the project or Propose edits.
  2. Inspect the provider, model and exact system/user text in Check before sending. Cancel if the context is too broad or sensitive.
  3. Tap Send. Read the streamed answer; expand tool timeline rows for exact text rather than a summary. Stop cancels the request.

Send approves a disclosed task, including bounded read-only follow-ups that may transmit more admitted file text without a fresh tap for each read. Read the expandable timeline to inspect exact results. Continue creates a fresh preview and needs Send; a pre-text rate failure can retry once with a visible, cancelable countdown.

Two separate approval doors

  • Apply / Reject changes: the model proposes a diff; only your Apply writes through the dedicated applier. There is no write tool.
  • Run / Skip: request_run creates a card; only your Run enters the normal RUN pipeline. Bounded real output/exit can return to the provider. There is no exec tool.
  • Undo AI changes: the last applied task has a journal limited to five files / 256 KB. It can refuse after conflicting manual edits; it does not undo commands, network traffic, packages or Git operations.

Nine controls inside the same boundary

  • Read window: smaller file slices, within 50–400 lines.
  • Working set: context depth within admitted paths.
  • Task memory: bounded task facts, not raw-chat persistence.
  • Answer detail: presentation, not more permissions.
  • Tool activity: display of the timeline.
  • Request inspection: always on; cannot be disabled.
  • Backup provider: a manual offer, never a silent transfer.
  • Budget extension: an offer inside the hard caps.
  • Read-only reviewer: review without new write/run powers.

S9: none of these controls widens what may be read, written, run or reached. Model/provider capability labels also cannot grant permission.

What survives—and what does not

Raw questions, answers, tool results and drawer titles are session-only. D6 keeps raw chat out of files, logs and backups. The drawer holds up to 20 conversations per project; follow-ups carry up to 8 turns. App death clears the session.

A separate, narrowly bounded task-memory cache may persist admitted non-secret file snapshots and structured findings/decisions/plan under no_backup/ai/task/: at most five files, 160 KiB of file content and 256 KiB total. It is not a transcript. Last-task undo preimages are another bounded store under no_backup/ai/undo/. Project deletion or deleting a provider key clears those task/undo stores.

Provider keys are encrypted with Android Keystore AES-256-GCM under no_backup/ai, not in the project. Explain last error and run-output context are secret-scanned; inspect the preview anyway.

A provider is a separate recipient

For AI: nothing leaves unless you send it; when you do it goes to the provider you configured—there is no CodeC server. A task can include scoped follow-ups. A connection test and a visible retry are also disclosed network actions.

Provider terms may permit retention or review; stateless requests are not zero retention. Never send keys, confidential material or personal data. Provider changes are manual with a fresh preview, not silent failover. There is no unlimited-use, accuracy or availability guarantee. No on-device model is shipped: Level13 is postponed and Level14 unauthorized.
