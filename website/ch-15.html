Custom Setup & Advanced Tools

Make repetitive work easier with shortcuts, a Makefile, search and organized terminal sessions.

What you will learn

  • Configure two harmless shortcuts and automate a small build.
  • Use Clang diagnostics, ripgrep and tmux without overstating their powers.

Before you begin

Ready Linux tools, Chapters 5/9/10 and a disposable project. Install only the verified packages you choose to use.

Adjust tools you can see

Settings → Terminal Extra-Keys & Shortcuts → Custom Extra-Key Shortcuts accepts comma-separated values. Try git status, make and tap SAVE SHORTCUTS. Return to Terminal and test a harmless shortcut in the correct folder before adding anything destructive. This is text/command convenience, not permission to bypass prompts.

Font size/family and separate editor/terminal theme choices are available. VS Code Dark+ is the default editor theme; Monokai, Dracula and GitHub Dark are also documented. Do not teach “dark only” or a retired engine selector from older notes.

Let a Makefile remember the command

Install make from Packages or pkg install make. Put these three files in one disposable project. Recipe lines in Makefile must start with a literal TAB, not spaces.

greeting.h

#ifndef GREETING_H
#define GREETING_H
#define GREETING "Hello from make"
#endif

main.c

#include <stdio.h>
#include "greeting.h"
int main(void) { puts(GREETING); return 0; }

Makefile

all: hello

hello: main.c greeting.h
	cc main.c -o hello

run: hello
	./hello

clean:
	rm -f hello

.PHONY: all run clean

Build, run, then remove only the named output

make
make run
make clean

Expected: a compile command, then “Hello from make”, then deletion of hello. main.c and greeting.h remain. make rebuilds when a listed prerequisite changes; that is why it beats retyping longer commands.

When a project needs a custom run

Ordinary RUN uses the active runnable source. Advanced multi-file projects can use the shipped project run configuration, including a project-root .codec.json override. Start with a documented Makefile before overriding launch behavior. Keep a known-good backup and do not paste an unreviewed build command into configuration.

Optional .codec.json for this Makefile project

{"build":"make","run":"./hello"}

This override makes the project build/run use those commands. Remove or restore your own override when returning to active-file exercises; otherwise a different source tab may still invoke the configured build.

Ask for a warning, then fix it

Where a compatible Clang toolchain is installed, compile warning.c with -Wall -Wextra. A package download and Android execution policy can still block the tool; follow automatic fallback guidance rather than replace cc.

warning.c · intentionally unused value

#include <stdio.h>
int main(void) {
    int unused = 7;
    puts("Read the diagnostic");
    return 0;
}

Use Clang explicitly when available

clang -Wall -Wextra warning.c -o warning

Expected: a diagnostic about unused, with wording/version dependent. Remove that declaration or use the value and compile again. This deliberately avoids demonstrating uninitialized-value execution as safe code.

Find a task in your source

Search a disposable note

pkg install ripgrep
printf 'TODO: improve greeting\n' > tasks.txt
rg -n "TODO" tasks.txt

Expected match

1:TODO: improve greeting

Quote the search text. No match can be a normal result; check the filename and working directory before blaming installation.

Keep sessions organized

Start a multiplexer

pkg install tmux
tmux

Inside tmux, start sleep 60. Press Ctrl-b then d to detach; from the shell, tmux a reattaches. Ctrl-b then % splits a pane. The prefix is a sequence, not a single combined chord with the final letter.

tmux can preserve a running shell session across detach/reattach. It does not guarantee survival when Android kills the app or its processes. Keep notifications and battery restrictions in mind; do not promise overnight builds from this exercise.

Personalize without losing recovery

Export source projects before major environment changes. Backup does not include the downloaded tools, settings or credentials. Use current status/heal/repair guidance for the environment, and Settings → Developer Options → View App Logs for evidence. Do not confuse Clear ALL Data with a harmless cache button.

Try it yourself

  1. Save the two shortcuts and test git status in your practice repository. Expected: a status result, not an automatic push.
  2. Change GREETING, run make run, and verify the updated output; make clean must leave source files.
  3. Detach/reattach a tmux session containing sleep 60 and observe whether the same session remains. Record Android interruption honestly if it occurs.

Common mistakes

  • Make recipes require TAB indentation.
  • An override can intentionally change active-file RUN behavior; keep it explicit.
  • tmux is not protection from all Android process killing.
