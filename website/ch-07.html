The Editor

Use fewer taps without giving up control of what enters your file.

What you will learn

  • Use completion, snippets, search and formatting intentionally.
  • Recover from a typing mistake and inspect diagnostics.

Before you begin

A disposable Auto project with hello.c and index.html; familiar with autosave and the file drawer.

Read the editor around the code

File icons identify types; tabs show open files and dirty state. The drawer is for navigation, while the Ln/Col status helps locate diagnostics. Autosave follows a short pause. The five-tab bar can reduce while a keyboard is up so the caret stays visible—close the keyboard or use the handle rather than assuming tabs disappeared permanently.

Your phone’s keyboard is the default. CodeC Keys and extra keys are optional tools, not mandatory replacements. Settings provides font and editor/terminal appearance choices; VS Code Dark+ is the default editor theme.

TAB accepts. Enter is still Enter.

  1. In a C file type a partial identifier or #inc. Read the offered text before accepting it.
  2. Use TAB ▸ for the ghost suggestion or tap an appropriate chip. The more control opens the larger candidate list; it is not an instruction to accept everything.
  3. Press Enter when you want a newline. Enter does not silently accept completion. Undo if you inserted the wrong text.

Word/line acceptance controls can accept less than the full ghost text. Suggestions combine language-aware identifiers, keywords and bundled snippets; an available suggestion is not proof that its code is correct for your program.

Try one snippet, then one expansion

Bundled friendly-snippets packs work without a remote completion service. Try for in a C file or def in Python and inspect the placeholders. Emmet is built in for markup/CSS:

Type in an HTML file, then accept an Emmet candidate

ul>li*3

Expected structure

<ul>
    <li></li>
    <li></li>
    <li></li>
</ul>

Other useful examples are ! for a document skeleton, div.card>p{Hello} for nested markup and m10 in CSS for a margin declaration. Keep the cursor in the matching language context; plain text is not an Emmet parser.

Search and formatting are reviewable changes

Use find/replace to inspect occurrences before a global replacement. Regex is more powerful than literal search and easier to misuse; start with literal mode on a disposable note. Undo/redo and per-tab state let you back out a mistaken edit.

Format can use clang-format when available, with a built-in C-indenter fallback. Formatting whitespace does not fix wrong logic. Compare the result before continuing. A missing semicolon may produce a squiggle with a tap-to-inspect diagnostic and quick fix; read the location, not only the color.

Keep the caret, not the clutter

When the keyboard, output panel or key rows change size, the editor brings the active caret into view. Scrolling away should not be punished by an unrelated jump. Very long lines can activate a display guard; split a huge generated line instead of assuming the file was rewritten.

A useful loop is type → pause for autosave → inspect → RUN. Keep the relevant file active; close irrelevant output or search UI when it reduces the working area.

Try it yourself

  1. Accept one C snippet, replace its placeholders and compile. Expected: no unresolved placeholder names remain.
  2. Expand ul>li*3, add three words, then RUN the HTML. Expected: three list entries.
  3. Replace a word in a disposable note, then Undo. Expected: original text returns; Enter still inserts a newline.

Common mistakes

  • A suggestion is a proposal, not a compiler guarantee.
  • Enter is not the completion-accept key.
  • Do not assume a TextMate grammar means its runtime is installed; packages and highlighting are separate.
