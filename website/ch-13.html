What you will learn

  • Use battery, sensor, speech, camera and intent commands.
  • Recognize missing hardware, permission prompts and explicit refusals.

Before you begin

Ready Linux userland and the CodeC Terminal in the foreground. Device capabilities vary; read prompts before allowing access.

The bridge and its inventory

CodeCApi lets terminal commands request app-side Android actions. It does not grant a shell arbitrary Android permissions. The verified source installs11 API scripts; codec-setup-storage is a separate storage helper. This inventory replaces older conflicting five/eight-script counts.

Read a battery snapshot

Battery command

codec-battery

Illustrative JSON shape · values are device-dependent

{"percentage":73,"status":"discharging","temperature":30.0,"health":"good","voltage":4000,"plugged":"none"}

The field is percentage, not level; percentage, temperature or voltage can be null when unavailable. This is an example shape, not a device-test transcript. Status is a string such as charging or discharging. Keep the raw result if you are diagnosing a script.

Read one sensor sample

Try available sensors

codec-sensor accelerometer
codec-sensor gyroscope
codec-sensor light

Accelerometer/gyroscope samples carry type and x/y/z. A light sample carries type and lux. Values vary; missing hardware returns an unavailable error rather than invented zeros. Cover/uncover the light sensor and compare two readings if your device has one. A one-shot read is not a continuous sensor logger.

Say something short

Speech request

codec-tts "Hello from the phone"

Expected on a device with working TextToSpeech: spoken text and a success result. A missing voice/engine or a busy/unavailable service may fail. This is not microphone recording and does not require inventing a microphone permission.

The request cap is32KiB (32,768 bytes). Empty or oversized text is rejected, not silently truncated. The bridge uses QUEUE_FLUSH; a new utterance can replace a pending one.

Take one photo with consent

Capture a named still image

codec-camera practice.jpg

Allow CAMERA only if you intend the capture. The bridge uses NEED_PERMISSION: while waiting for permission, then CAPTURING: while Android handles the photo, and a final OK:path or error. CLI wording can turn markers into a human-readable message. Cancel or deny if you do not want a photo; do not repeatedly issue new requests into a pending flow.

The output is under $PREFIX/tmp/codec-api/camera/. Use a simple basename made of letters, digits, dots, dashes and underscores ending .jpg/.jpeg/.png—not a directory traversal or an absolute path.

Inspect the camera output directory

ls "$PREFIX/tmp/codec-api/camera"

Expected after a successful capture: practice.jpg. A missing camera, cancellation or denial is a valid outcome to report, not a reason to claim a device pass.

Open a destination deliberately

Open a public page via the Android handler

codec-intent view https://github.com/pabi277/CodeC

view, dial and send are the allowed actions; view/dial data must use a permitted URI scheme. The bridge does not expose arbitrary private activity components. The example opens a browser and can contact GitHub; do not run it expecting a no-network action.

Clipboard/share/notifications also have real consequences: use harmless text, inspect a share sheet and keep private clipboard content out of public logs.

Combine a reading and speech

This Bash example extracts the documented integer percentage with sed. It refuses a missing/null/non-numeric value instead of speaking fabricated data. Save it as battery-greet.sh:

battery-greet.sh

json=$(codec-battery) || exit 1
level=$(printf '%s\n' "$json" | sed -n 's/.*"percentage":\([0-9][0-9]*\).*/\1/p')
case "$level" in ''|*[!0-9]*) printf 'Battery unavailable\n' >&2; exit 1;; esac
codec-tts "Battery at $level percent"

Run the glue script

bash battery-greet.sh

Expected: your current battery percentage spoken, or a clear failure. This depends on a real device and the foreground bridge. A host syntax check cannot certify it.

Try it yourself

  1. Read battery JSON and identify percentage, including what null would mean.
  2. Run the short speech command; report heard speech separately from command status.
  3. Optionally capture practice.jpg and confirm the listed path, or record denial/cancellation honestly.

Common mistakes

  • Do not use a made-up JSON key called level.
  • A permission prompt is not a silent grant, and absent hardware is not repaired by retrying.
  • Oversized speech is rejected. This bridge is not an unrestricted background API.
