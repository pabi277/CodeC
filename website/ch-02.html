Your First C Program

A source file becomes a program in two steps: compile it, then execute it.

What you will learn

  • Create and run hello.c.
  • Use the terminal compile/run loop and understand ./ .

Before you begin

Chapter 1. Built-in C needs a supported ABI; terminal commands need a ready shell.

Write the complete file

Create FirstC with Auto (detect), then hello.c in its root using the Editor file drawer. Alternatively, use the Editor’s Files & Projects sheet to work in Single files. Keep the file ending .c; paste the complete program, not its expected output.

hello.c

#include <stdio.h>

int main(void) {
    printf("Hello from CodeC!\n");
    return 0;
}

stdio.h declares printf. main is the entry point; return0 reports successful completion. The semicolon ends a statement. The backslash-n creates a new line.

Take the quick route

Wait for autosave and keep hello.c active. Tap RUN. Auto uses the available compiler path without an engine selector. On a supported ABI, bundled TCC needs no package download. Expect:

Expected program output

Hello from CodeC!

A compile error is not an app crash. Read the first diagnostic, line and column before changing the file. A blocked executable or ABI error belongs to compiler troubleshooting.

See the two commands

In Projects, use hello.c’s ⋮ → Run in Terminal to establish the correct project folder. When that run finishes, type the following separately, pressing Enter after each:

Compile hello.c

cc hello.c -o a.out

Run the executable

./a.out

A successful compile may print nothing. The second command should print the greeting. The -o option names the output; keep it last for the TCC frontend.

Why the dot and slash matter

The shell normally searches PATH for a bare command. The current folder is deliberately not on PATH. ./a.out means “the file a.out in this directory.” Do not add . to PATH to make a lesson work.

Your explicitly named output stays next to the source here in app-private project storage. That is different from CodeC’s own temporary run artifacts. Editing hello.c does not rewrite an existing executable: compile again before rerunning.

Make the result yours

Change the greeting, let the save finish and repeat both commands. Rename the executable in the compile command to myhello, then run ./myhello. Expected: the changed greeting under either filename. Interactive scanf/getchar examples belong in Terminal so you have a keyboard input path.

Try it yourself

  1. Print three separate lines. Expected: all three appear in order.
  2. Build with cc hello.c -o myhello and run ./myhello. Expected: the same greeting.
  3. Only in this disposable project, remove the generated a.out with rm a.out, confirm with ls, and rebuild. Expected: source remains intact.

Common mistakes

  • A missing ; is a compile error; use the diagnostic and the missing-semicolon quick fix where offered.
  • command not found can mean you forgot ./ or are in the wrong directory.
  • Do not run yesterday’s binary after editing today’s source.
