Package Manager

Install a useful tool, understand its status and leave trust verification intact.

What you will learn

  • Install and verify a package.
  • Distinguish repository roots, installed binaries and recovery actions.

Before you begin

Optional Linux setup completed in Terminal; internet for package metadata/downloads.

Start with one tool

Open Packages and find nano. AVAILABLE means it is not installed according to the app’s check; INSTALL starts the operation. After success, INSTALLED and a supported RUN action tell a different story. Do not treat a catalog row as proof that an interrupted download completed.

Terminal alternative

pkg install nano
nano --version

Confirm if prompted. Expected: the package installs and nano reports its version. If unavailable, read the repository/environment error rather than add another ecosystem’s source.

Refresh, inspect, then change

Inspect and refresh

pkg status
pkg update

status explains environment health; update fetches current metadata, it is not the same as upgrading every installed package. Use pkg upgrade when you want to review updates. The -y flag pre-approves confirmations; omit it while learning so you see what will change.

Signatures are not an optional nuisance

CodeC’s bootstrap is SHA256-verified, staged and atomically installed. Its package source uses OpenPGP signed-by verification and fails closed. Never replace signed-by with trusted=yes, ignore a failed signature, or add official Termux repositories. The CodeC prefix and package build rules are different.

Only trusted, source-built CodeC packages belong here. Do not overwrite cc or turn the real bash executable into a script wrapper.

Read the inventory accurately

The complete local package table lists33 curated build roots from the verified config. Dependencies/subpackages make that different from a count of installable programs. Python’s package is python and executable python3; ripgrep runs as rg; libllvm is a build root that produces Clang subpackages.

The bootstrap separately seeds core shell/package tools including curl. OpenSSH and Vim are deferred, not magically present because a Termux tutorial mentions them. Your installed build and repository metadata decide current availability.

When an operation stops halfway

  1. Copy the exact error and run pkg status. Distinguish network failure, signature failure and a missing executable.
  2. Use the app’s pkg heal / pkg repair guidance when the environment reports an interrupted or damaged installation. Read the action before confirming.
  3. Keep other navigation available, but let one package operation finish before another mutation. Back up important source before larger recovery work.

Try it yourself

  1. Install nano and record its version line. Expected: a real binary response, not just a changed badge.
  2. Find Python3 in Packages and compare its install package name with python3 --version. Install only if you want the later chapter.
  3. Explain why33 build roots does not mean33 installed apps. Expected: mention dependencies and subpackages.

Common mistakes

  • pkg update refreshes metadata; it is not an APK updater.
  • A failed signature is a stop signal, never a prompt to weaken trust.
  • OpenSSH is deferred in this verified config; do not invent pkg install openssh instructions.
