## Design

`app/src/test/java/com/codeci/ide/AiLevel6FixtureSupport.kt` materializes four disposable projects in a JUnit temporary folder: C, Python, JavaScript, and HTML. Each has:

- a 300-line normal source with distinct first, middle, and last-line markers;
- a 2,000-line generated source whose tail marker is beyond the reader prefix;
- a one-line minified source;
- a binary file containing NUL bytes;
- a synthetic `.env` with the literal value `not-a-real-key`;
- an escaping symlink to a sibling fixture-only text file; and
- a Markdown file containing inert prompt-injection test text.

The files are generated by test code, not committed as bulky datasets. No provider is contacted. For the request-size metric, the test builds the same hypothetical NVIDIA JSON body through `NvidiaRequest.body` and measures its UTF-8 bytes; it never calls `client.stream` or sends the body.

`AiLevel6BaselineTest.kt` uses the real `AiProjectReader`, `AiToolRunner`, `AiToolPolicy`, `AiToolProtocol`, `AiAgentPolicy`, `AiAgentPrompt`, and `AiRepoMap` on the fixture tree. The tests record current behavior rather than changing it:

1. fixture inventory and first/middle/end markers;
2. current AI walk excludes `.env`, binary, and escaping symlink while retaining the injection text as ordinary data;
3. the result marker is present at the runner boundary but lost at the 1,200-character timeline/model boundary;
4. a request for lines 1,900–2,000 returns a single line near the 24,000-character prefix, never the generated end marker; and
5. 49 identical valid read blocks yield 24 allowed calls + 25 budget refusals; 24 identical executions yield 23 duplicate executions, and the mixed display becomes “49 of 24 reads”.
