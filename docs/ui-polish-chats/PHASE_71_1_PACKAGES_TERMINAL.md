## Discussion record — 2026-09-29 (owner: "71.1 start")

Evidence the chat read in the checkout on `main` @ `679bc69` (source reading only —
no device, no run; every line is a reading, not a reproduced defect):

1. **Packages row never learns an install failed.** `ModulesScreen.PackageCardRow`
   builds `InstallFacts(..., progress = null, failed = false)` every time. After
   INSTALL the row sets `installRequested = true` and polls the disk every 1.5 s
   in a `while (!installedNow)` loop with no exit; the primary button is
   `enabled = !installInFlight`. A failed install (offline, disk, signature)
   therefore leaves a disabled INSTALLING button until the row leaves
   composition. `InstallLabel.RETRY` / `UPDATE` and `InstallMoment.failureKind`
   exist and are unit-tested but unreachable from the screen.
2. **Terminal toolbar ⬇ ("Install userland")** calls
   `TerminalViewModel.installUserland()`: closes **all** sessions and forces a
   reinstall, in one tap, with no confirmation. Its own failure hints
   (`SetupGatePolicy.dontCloseText`, `TerminalStatusLabel`) point the user at
   this same button ("tap ⬇ to try again").
3. **Session identity.** The session switcher is a bare number in the top bar;
   Packages INSTALL / RUN / UNINSTALL / Quick Actions fire a toast
   ("Installing X…") and switch tab, sending into the *active* session without
   naming it.
4. `pkg` is generated by the app (`ShellEnvironment.pkgScript()`, rewritten by
   `ShellBootstrap` every time the shell is prepared). It already keeps
   `$STATE/transaction.pending` for the life of an install/upgrade and removes it
   on both success and failure, and its failures go through `error()` /
   `return $_err`. It has no exit-status report the app can read.

Questions asked, **owner answers verbatim (option ids as chosen in the dialog):**

- Failed install row → **`detect_exit`** — "Detect the real result: wrap the
  command so the shell reports the exit status, which gives a true RETRY."
- Terminal ⬇ → **`confirm`** — "Add a confirm dialog: says what will happen (all
  sessions close, tools re-downloaded). Same icon, same look."
- Session identity → **`name_in_toast`** — "Name the session: the toast and the top
  bar say the session, e.g. 'Session 2'. No layout change."
- Anything else → **`review_more`** — "I check the other checklist items (restart,
  copy/paste, extra keys, notification) and report before you decide."
